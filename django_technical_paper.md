# Django Review: Settings, Models, Security, and ORM

## Introduction

Django is a Python web framework used to build secure and database-driven web applications. Its settings, models, middleware, and ORM provide the main structure for configuring applications, handling requests, defining database data, and interacting with databases.

## 1. Settings File

### Secret Key

The `SECRET_KEY` is a private value used by Django for cryptographic signing, including sessions, password-reset tokens, and other security-related operations. It must be kept secret and should not be committed to a public repository.

### Default Django Apps

Django includes applications such as `admin`, `auth`, `contenttypes`, `sessions`, `messages`, and `staticfiles` by default. A project can also include custom applications and third-party applications.

### Middleware

Middleware is a layer that processes HTTP requests and responses before or after they reach a view. Common middleware handles security, sessions, authentication, CSRF protection, messages, and common HTTP operations.

### CSRF

Cross-Site Request Forgery (CSRF) is an attack where a malicious site attempts to perform an unwanted action using a user's authenticated session. Django provides CSRF middleware and tokens to protect unsafe requests such as POST requests.

### XSS

Cross-Site Scripting (XSS) occurs when untrusted content is executed as JavaScript in a user's browser. Django templates automatically escape most variable output, which helps prevent common XSS attacks.

### Clickjacking

Clickjacking tricks a user into clicking something different from what they see. Django provides clickjacking protection middleware that can use HTTP headers such as `X-Frame-Options`.

### WSGI

WSGI stands for Web Server Gateway Interface. It is a standard interface between Python web applications and web servers, allowing servers such as Gunicorn to communicate with Django applications.

## 2. Models File

### On Delete Cascade

`on_delete=models.CASCADE` means that when a referenced parent object is deleted, related child objects are also deleted. For example, deleting a `Match` can delete its related `Delivery` records.

### Fields

Django model fields define the type and behavior of database columns. Common fields include `CharField`, `IntegerField`, `DateField`, `BooleanField`, `ForeignKey`, and `ManyToManyField`.

### Validators

Validators are functions used to check whether a value satisfies specific conditions before it is accepted. Django provides built-in validators such as `MinValueValidator`, `MaxValueValidator`, and `RegexValidator`.

### Python Module vs Class

A Python module is a `.py` file containing Python code, such as functions, variables, or classes. A class is a blueprint for creating objects and defining their attributes and behavior.

## 3. Django ORM

### ORM Queries

Django ORM allows developers to work with database records using Python instead of writing SQL directly. Queries can be executed through the Django Shell using methods such as `filter()`, `get()`, `create()`, and `delete()`.

### ORM to SQL

Django can show the SQL generated by a QuerySet using the `query` attribute. For example, `print(MyModel.objects.filter(id=1).query)` displays the SQL query generated by Django.

### Aggregations

Aggregations calculate summary values across multiple database records. Common aggregate functions include `Count`, `Sum`, `Avg`, `Min`, and `Max`.

### Annotations

Annotations add calculated values to each object returned by a QuerySet. They are useful when each record needs additional calculated information, such as the number of related objects.

### Migration Files

Migration files describe changes to Django models and allow those changes to be applied to the database. Commands such as `makemigrations` create migrations, while `migrate` applies them.

### SQL Transactions

A database transaction groups multiple database operations into a single logical unit. A transaction can be committed when all operations succeed or rolled back when an error occurs.

### Atomic Transactions

Django's `transaction.atomic()` makes a group of database operations atomic. If an exception occurs inside the atomic block, Django rolls back the transaction so that partial changes are not saved.

## Conclusion

Django combines configuration, security middleware, models, and ORM features to simplify web application development. Understanding these concepts helps developers build applications that are maintainable, secure, and reliable.
